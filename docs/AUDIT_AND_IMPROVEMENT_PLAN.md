## 根本から見直す理由

現行16タイプと64分類、相性率、120%の強度は独自ルールであり、引用できる研究の分類・尺度そのものではない。論文を後付けするだけで既存の数値や分類が検証されたことにはならない。

全32問を中間の回答にするとDWNX-A、8軸は52、52、52、53、53、53、52、52、独立Cは51となるが、説明は強い性格像になる。Cの直接測定はQ7の1問だけで、旧データにCがない場合は62を補っている。相性は初期70と加算・固定値による算出であり、成功率ではない。これらを精密な測定として見せることをやめる。

画面は見出し、長文、数値、タグ、グラフ、共有ボタンが競合し、縦長画面ではサブナビに到達するまでの負荷も大きい。320pxのQ1は収まるが、文字が小さい。図鑑モーダルはEscapeで閉じず、dialogの役割指定もない。タグは固定候補中心で、利用者の言葉を受け止めにくい。

## 新しい実装方針

1. 研究が支持する概念と、このサイト独自の仮説を分ける。根拠のない出現率・精度・相性確率を表示しない。分類の断定を避け、回答から確認できる傾向を先に返す。
2. 回答とタグは端末内を基本とし、改善へのデータ提供は18歳以上の任意参加にする。参加しなくても同じ診断を利用でき、送信したデータの撤回を可能にする。
3. D1で同意済みデータと撤回を管理し、R2には個人回答を含まない集計・モデル版の記録を置く。定期処理で品質を点検し、データ不足・品質未達では更新しない。テストデータを利用者データに混ぜない。
4. 画面は短い概要から必要な部分を開く。点滅・過剰な発光・装飾・情報の並列を抑え、日本語の文節と余白を整える。利用者向けに内部仕様・アルゴリズム説明を混ぜない。
5. 自由入力タグを正規化・重複整理・分類し、意味やNGを勝手に変えない。利用者による修正を次回の整理に反映する。私的なタグを無断で全体公開しない。
6. 広告は診断と独立させる。広告承認と実在する提携URLを確認してから配信する。回答・好みの広告ターゲティングは行わない。

## 研究と設計の出発点

- [Joyalら 2015](https://pubmed.ncbi.nlm.nih.gov/25359122/) は成人の性的空想を調べ、一般性の決めつけへの注意と、主導・委ねのテーマの併存に関わる結果を示す。このサイトの16分類や得点を検証した研究ではない。
- [Joyal 2015（単著）](https://pubmed.ncbi.nlm.nih.gov/26797067/) は集団・下位集団の扱いによって一般性の解釈が変わる問題を扱う。自己選択されたサイト利用者のデータを一般人口へそのまま広げない。
- [W3Cの認知アクセシビリティ指針](https://www.w3.org/WAI/WCAG2/supplemental/objectives/o1-understandable/) を踏まえ、目的、操作と結果のつながり、読み順を明確にする。

## 収益化と費用

GoogleはSM等を含む性的な内容を広告供給の制限対象としている。[Googleの制限コンテンツ](https://support.google.com/publisherpolicies/answer/10437795?hl=ja)
A8.netはアダルトサイトの登録を禁止している。[A8.netの禁止事項](https://www.a8.net/compliance/prohibited-matter.php)
サイトのテーマを隠して審査を通そうとせず、対象サイトを認める掲載先・直接スポンサー等の条件を確認する。現時点で利用可能な広告サービスは確定していない。

静的ファイル配信はCloudflareの料金説明上無料だが、データ収集用Worker、D1、R2を追加すると別の利用量が生じる。[Cloudflare Static Assetsの料金](https://developers.cloudflare.com/workers/static-assets/billing-and-limitations/)
新しいAPIは経路を限定し、Bot検証・入力上限・受入上限・処理時間上限・定期処理の件数上限を設ける。有料生成APIは使わない。アカウント全体の請求を5ドルに固定できるという保証はしない。

## Geminiの経緯を踏まえた判断

2026年10月18日、Chromeで開かれた「性癖分析ウェブサイトの企画」の会話を参照した。出発点は、MBTI風の手軽さに、共依存・ギャップ・属性などの概念的な性癖、ペア比較、Xで比較できる画像を加える企画だった。その後、独立した主導・委ねの好み、想像と現実の希望、情景による質問、攻守の変化、グループと共有表現へ発展していた。

この流れの独自性は残す。一方、Geminiが述べた「数理的・学術的裏付け」は、現行の質問・分類を検証した実測データではない。主導と委ねを別々に質問することと、統計的な無相関や一次独立性が確認されたことは区別する。主導・委ねと、痛みを含むS/Mの概念も完全な同義にはしない。現行の新質問は前者を振り返るもので、痛み・医療的状態・相手への加害欲を測る検査ではない。

## 次の改善計画と判断の条件

| 優先度 | 問い・作業 | 次へ進める条件 |

| P1 分類 | 16タイプやサブタイプは実用上役立つか。連続的な好みをタイプへ丸める価値と誤解を比較 | 別の検証データで再現し、利用者に分類を強制せず、不確かさを説明できるまで自動採用しない |
| P1 自律更新 | 日ごとの回答偏り、欠測、重複、α以外の指標を監視。質問の改善候補を作成 | 自動更新は集計参考値まで。新たな質問票・分類の採用はレビューと版分けを経る |
| P1 UX | 初めての人が説明なしで回答・自由タグ・共有範囲を理解できるか。実iPhone/Safari、キーボード、スクリーンリーダーで確認 | 完了率や理解の評価は実測する。ブラウザー試験成功を人間の使用感やアクセシビリティ認証の代わりにしない |
| P1 事業 | 成人向けテーマを認める提携先・直接スポンサーの条件と掲載URLを取得 | サイト承認・実在URL・期限・報酬条件を確認。ID未取得を収益ゼロの実績値や将来売上の根拠にしない |
| P2 集客 | 読みものを具体例と研究にもとづいて充実。タイプ記事のテンプレート重複を減らす。検索登録を確認 | クロール可能と実際にインデックスされたことを分けて確認。SafeSearchを回避する目的でテーマを偽装しない |
| P2 成長 | 訪問→回答開始→完了→タグ編集→共有→再訪を測りたいが、好みと広告を結び付けない | 測定目的・保存範囲・同意を先に決め、必要な集計だけ導入。現在はこの行動ファネルを収集していない |

| P2 運用 | 請求・Cron失敗・Bot受付拒否の監視、復旧の机上手順と訓練 | R2の非公開、削除記録の再適用、品質ゲートを維持。アカウント全体の費用が5ドルで固定されるとは約束しない |

本番の正常受付と撤回を確認する場合、合成の確認用回答は直後に取り消し、統計に混入させない。品質条件を満たした実参加データがない間は、参考値非公開を正常状態として扱う。
