# 画面設計

参照: home-concept.png / result-concept.png。生成画像を配置するのでなく、実際に操作できる画面として実装する。

- 背景 #13111b、面 #1b1826、文字 #f4f0fa、副文字 #bcb4ca、アクセント #b99ae6。発光・点滅・グラデーションを使わない。操作に伴う短い遷移は認識を助ける範囲に抑える。
- 本文16px以上・行間1.8、本文幅最大68文字程度。短い語を無理に均等分割せず、日本語の禁則処理に従う。見出しの改行は意味の区切りのみ。
- トップ: 目的、40問の開始、見本、3つの読み物。長さを選ぶ入口は廃止。結果: 二つ名、条件で見える別の顔、刺さる場面、共有・比較。細部とタグは下で必要に応じて開く。
- タグは24個まで、32文字以内。好きと境界線を分ける。表記を整え、自動分類し、ユーザーの修正をその端末で覚える。共有は明示的な選択式。
- 病名、科学的に検証されたタイプ、相性成功率、人口順位を示さない。根拠・限界は独立した読み物に置く。
- 旧版の端末データは書き換えない。旧URLは現行の入口へ転送し、別診断は公開しない。旧版の質問・判定は非公開ソースとして回帰確認に残す。過去のデータ提供の撤回は引き続き受け付ける。

本文には対応ブラウザーで `word-break: auto-phrase` を適用。質問と選択肢、共有画像には同梱したBudouXで文節を作り、未対応のブラウザーでも語尾が孤立しにくくする。二つ名は意味のまとまりで折り返す。[Googleの解説](https://developers-jp.googleblog.com/2023/09/budoux-adobe.html)。iPhone/Safariの実機確認は別途必要。

2026-10-19、v18の実操作レビューで、390pxの質問画面に選択肢と「次へ」が収まるよう質問中のナビゲーションを簡略化した。4人比較の6組は開閉式にし、結果の全体を先に見渡せるようにした。タグ編集時は結果演出を再実行せず、操作対象へのフォーカスを戻す。質問180ms、結果420ms、ダイアログ160msの遷移を設定し、動きを減らす環境設定では停止する。


## v19の対象と体験

第一対象は、日本語のXで性癖の話題に触れ、「SかMか」だけでは好みを言い切れず、自分に合う鋭い言葉を見つけて共有したい18歳以上の成人。実体験や専門用語の知識を前提にしない。本人の性的指向、性別、交際状況は仮定しない。第二の利用場面は、信頼する相手や友人との好みの会話。これは狙う層の定義であり、市場で支持された証拠ではない。

持ち帰れるものは、好きの組み合わせから作る短い二つ名、自己認識と具体的な希望との意外な対比、自分で足せる条件、選んだ言葉だけの共有画像。入口の「SかMか、だけじゃ言い切れない人へ」、検索・OG説明、開始前の「自分がしたい・されたい」、結果と投稿文を同じ目的へ揃える。40問への一本化を維持し、16の関係性は探索用の図鑑へ移す。診断の種類や版、数式を選ばせない。

Geminiの12軸案は初期仮説として採用し、拘束と独占を加える。新しい2成分は2問以上、その他の主成分は3問以上の手がかりを必要とする。拘束は共通の場面と、する・されるのどちらかを確認し、反対の役への低反応で好みを打ち消さない。相手の主導を望むだけでMにせず、世話を焼くことだけで独占を推定しない。S/Mの併存は表現できるが、統計的独立や12成分での網羅は未検証。自己認識と場面の対比は、無意識やトラウマの推定には使わない。

## 競合を踏まえた立ち位置

2026-10-19の一次資料確認。[BDSMTest](https://bdsmtest.org/info) は、初心者から経験者のBDSM・kinkのラベル探索を提供する。[KinkTypeの現行説明](https://kinktypetest.com/methodology) は24問で、主導と委ね、場面による違い、保留、手元での処理を既に扱う。検索結果に残る旧41問・12プロフィールの説明を現行と混同しない。複数軸、プライバシー、結果比較だけを独自機能とは呼ばない。[日本MBTI協会](https://www.mbti.or.jp/attention/) が説明するMBTIと、[16Personalitiesの理論](https://www.16personalities.com/articles/our-theory) も同一視しない。

HEKI16では「余裕を崩したい／崩されたい」「わからせ」「共依存」など日本語の場面と多面的な選択肢を入口にし、固定カテゴリの正解を渡すより、二つ名・本人の見立てとの対比・本人による言葉の仕上げ・X向け画像を一続きにする。この組み合わせを製品の強みとして磨く。世界初、競合にない、科学的に優れるとは主張しない。[SMC研究](https://link.springer.com/article/10.1007/s10508-016-0789-0) は関心と行動、する／されるを区別する参考であり、本アプリの質問や12成分を検証したものではない。

## 4項目の受入条件

| 項目 | 実装・画面での条件 | 人間の利用で残る確認 |
| --- | --- | --- |
| UI/UXにこだわる | 320/390pxで選択・戻る・保留・再開・結果・共有・比較が完了。文節改行、固定の次ボタン、情報の開閉、動きを減らす設定。内部仕様の説明を主画面へ入れない | iPhone実機、支援技術、40問の疲労感 |
| 対象を定める | 上記の第一対象と利用場面を明示し、専門知識なしで自分の希望から答えられる | 狙う層での完了率と再訪、対象との一致 |
| 訴求と体験を揃える | 入口・見本・検索説明・質問・二つ名・投稿文が「自分の好みを言葉にする」体験を提供 | 期待とのずれ、名前の納得感と意外性 |
| 競合を踏まえ独自性を磨く | 現行の一次資料と比較し、単なる多軸化ではなく、日本語の鋭い場面→本人の言葉→共有の連続性を作る | 競合から選ぶ理由、自然なX共有・拡散 |

実利用者の反応なしに「バズる」「市場適合」「人間が使いやすい」を実証済みにしない。四つの実装条件を満たした後は、未知を埋めるための無制限な機能追加や同じ検証を繰り返さない。


## v20：初めて答える人と、狭く深い好み

主導を楽しむことと意地悪を楽しむことを同じ問いで加点しない。Q7を「任せたいと言われた時の主導」にし、Q16は途中の役の逆転を尋ねる。嫉妬を向けられる場面と、自分の感情が揺れる恋も分ける。見た目と文脈、駆け引きと甘さの比較表現を外し、どちらも好きな人が答えられるようにする。「わからせ」は「最後は参りましたと言わされたい」という具体的な場面で入口を作る。40問の順番・一つのコース・16件の関係性図鑑を維持する。

主導の主項目はQ1/Q7/Q38、SはQ3/Q5/Q33。主成分の手がかりには原則3問、拘束・独占・甘やかしの各方向には2問以上を使う。二つの強い回答を別の場面への低反応だけで消さないため、強い傾向の基準を見直した。甘やかしは、与えるQ26/Q29、受け取るQ4/Q30、余韻Q26/Q32を別々に確認し、反対の役への低反応で平均を下げない。医学的な尺度や検証済みの閾値という意味はない。

二つ名は任意の接頭語を付ける方式から、役と具体的な手がかりに合う文章へ変える。「囁きで落ちる司令塔」「手綱を預ける小悪魔」など、同じ強さでも好みの方向を区別する。広い軸が強くなくても、声や装いなど複数の回答で確認できた好みには言葉を返す。一部だけ強い、広く少し興味がある、今回の場面には刺さらない、未回答で分からない、を同じ空の結果にしない。意外性は自分の見立てと具体的な希望、併存する好みから作り、無意識や人格を推測しない。

主画面は短い説明と一つの場面を先に見せる。実際に選んだ場面を開いて確かめられるようにし、共有画像では短い一言に絞る。受け取った結果からは一度の操作で自分の診断を始められる。相手の結果と見本の投稿文は、本人の診断結果を名乗らない。書き足した名前・条件・自由タグは再診断でも保持し、共有への追加は初期未選択を維持する。

質問の意味とルールが変わるため質問票をunified40-3、保存領域をv3、共有をH6とする。H4/H5は読み取り専用の互換処理で当時の結果を維持する。過去の回答を新しい質問への回答に変換しない。D1の提供・撤回とR2の定期点検は現行の質問票だけを集計し、過去の提供の撤回を維持する。

具体的な場面に強く惹かれていても広い成分全体は強くない場合、詳細もその場面の言葉で示す。たとえば声の二つの手がかりが揃った人を、他の感覚への低反応で「五感は控えめ」とだけ表示しない。この場合は全般的な強さの棒を出さず、該当する言葉を見せる。
