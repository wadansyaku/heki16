# HEKI16 統一診断案

2026-10-18の合意案。2026-10-19に40問・16タイプとして実装・公開した。以下は過去の設計記録で、現行仕様ではない。現在の24場面と判定は `src/nocturne.mjs`、二つ名と図鑑は `src/dossier-catalog.mjs` に集約している。`src/content.mjs` と `src/diagnosis.mjs` は既存共有リンクの読み取りのために保持している。実装と検証の結果は `AUDIT_AND_IMPROVEMENT_PLAN.md` のv18節に記録した。

## 今回の合意と狙い

- 「自分がしたい・されたいこと」を診断の中心にする。
- 旧版の具体的な性癖、質問の鋭さ、独自の組み合わせを残す。言葉は短く洗練する。
- 論文による検証を公開の前提にせず、創作的な仮説として、納得感・意外性・共有したさを磨く。
- 短縮版・完全版・旧版・新版を利用者に選ばせない。一つの質問票、一つの判定、一つのタイプ辞書を使う。
- 問数は固定上限ではない。網羅性と、複数の質問による判定を優先する。
- グラデーション、過密なカード、点滅、内部仕様の説明を利用者の画面に戻さない。

目指す体験は「自分の性癖に名前がつく。しかも、どんな場面で別の顔が出るかまで言い当てられる」。

「性癖」を一般的な恋愛傾向へ薄めない。一方、推しの展開を眺めたいことから、本人がその関係の当事者になりたいと推定しない。

## 一本化する内容

第一候補は **40問・16タイプ**。40問は今回の編集上の提案であり、統計的に最適とわかった数ではない。

旧版Q1〜30のテーマを使い、主語と長さを整える。旧Q6の「独占したい」と「されたい」は分ける。旧Q24・25の場面選択は残し、選んだ場面自体を判定に反映する。旧Q31・32の「欲望に正直か」「昔から自覚があったか」は外し、距離感、役割、反応の確認に枠を使う。

構成は30の既存テーマ＋10問の補強。36問は好みの強さ、4問は自分が入りたい場面を選ぶ。同じ40問を全員に出し、回答による別コースや追加診断を作らない。

32問の旧エンジンを読み直すと、Cへの直接加点は旧Q7だけだった。また、他の31問をすべて否定して旧Q32だけ最大肯定しても、天性覚醒のO判定になる。好きな場面への反応を読むことと、自覚の古さを読むことを混ぜない。

## 一つの結果を作るロジック

### 主分類は16タイプ、S/Mは別に読む

16タイプの骨格は旧版の四つの組み合わせを継ぐ。

| 組み合わせ | 読むこと | 混同しないこと |
|---|---|---|
| 主導／委ね | 自分が持ちたい主導権 | 主導＝S、委ね＝Mとはしない |
| 重愛／クール・余白 | 持ち込みたい関係の重さや距離感 | 独占したいことと、されたかったことを同一にしない |
| 文脈／属性 | 気持ちが入る入口 | 見た目好きなら物語が嫌い、とはしない |
| 背徳／聖域 | 欲しい熱や余韻 | スリル好きならケア不要、とはしない |

それぞれの両側を独立して得点化し、強い方をタイプの短い要約に使う。片方の肯定から他方を減点しない。これに「相手の反応を崩したいS」と「自分が翻弄されたいM」を別々に持たせる。S/Mの両方が強い、両方が弱い、主導したいのにMも強い、委ねたいのにSも強い、を潰さない。

ここでのS/Mは、今回の質問が扱う焦らし・反応・翻弄の好み。未質問の痛みや行為への希望を追加で推定しない。

主分類の得点と表現を支える設問を少なくとも三つ確保する。質問に関連しそうという理由だけで、あらゆる項目へ薄く加点する設計を避ける。

### 得点と境界の扱い

- 強さの回答を「刺さらない＝0点」から「ど真ん中＝100点」まで25点刻みとし、各要素の主項目の平均を土台にする。場面選択は別の確認情報として使い、順番を点数へ置き換えない。
- 主項目が三つ以上回答されていることを主要得点の条件にする。補助項目は主項目と逆の結論を作らず、表現の選択に使う。この初案では、説明しづらい多数の補正係数を持ち込まない。
- 高い反応の仮基準を70点、両側の差を強く読む仮基準を15点とする。これは診断内の編集上の初期値。強い表現には平均だけでなく、主項目の複数が75点以上かも確認する。
- 得点はサイト内のスコアであり、人口順位、出現率、精度、相性成功率に見せない。
- 同じ質問数を持つことだけで網羅性が満たされたとしない。主な判定には三つ以上の設問、裏スイッチや自動タグにも複数の独立した回答を要求する。
- 主導／委ねやS/Mが両方高くても、片側を消さない。両方好きという回答だけで、毎回役割が入れ替わる人とも決めない。
- 「まだわからない」は欠測として扱い、好みが弱い回答や両方好きな回答へ置き換えない。
- 基本タイプは四組のそれぞれで得点が高い側を使う。差が15点未満なら、混ざる側の好みも結果文へ必ず反映する。完全同点では複数の場面回答で確認し、それでも決まらない項目を機械的に先頭の文字へ倒さない。
- 回答が揃わず、偏りも見えない場合まで強烈な一タイプを返さない。これは別の診断コースや17番目のタイプではなく、判定材料が不足した状態。
- 一問の変更だけで主要な分類が反転しやすい箇所は、重み・文面・境界の見直し対象にする。境界にいる回答の変化まで完全に抑えるとは約束しない。
- 「昔から好きだった」「欲望に正直でいたい」を、全スコアの増幅や生まれつきの人格判定に使わない。
- 同じ回答は同じ結果になる。利用者が見たタイプが、翌日の集計で黙って別物になる設計にはしない。

## 見せる順番とX共有

トップのコピー案は「あなたの性癖に、名前をつける。」。主操作は「性癖を診断する」の一つ。問数の選択、旧版への誘導、研究や内部仕様の説明は置かない。

質問は一画面に一問。読む対象は質問と回答、控えめな進捗、戻る操作だけにする。毎問の番号ドット一覧、複数色の強い縁取り、装飾用の細かなタグは外す。章名は小さく固定し、回答のたびに画面が明滅しないようにする。

## 相性、タグ、データの育て方

相性は同じ40問の結果を入力にする。「二人だとどんな主導権・駆け引き・甘やかし方になるか」を具体的に返す。いきなり成功率を出すより、「焦らす側と挑む側」「二人とも甘やかされ待ち」「攻守が入れ替わる二人」のように、会話や投稿になる組み合わせを作る。両者を入れ替えても意味が変わらず、与えたい側と受けたい側が対応する判定にする。

自由タグは、追加、表記整理、分類の提案、本人の修正の保持を続ける。タグを書き換えて回答由来のタイプまで変えない。自分用のタグと、共有画像に載せるタグを区別し、本人が掲載を選ぶ。

自動処理で育てる対象は、タグの表記候補、回答分布、戻りやすい質問、結果への「しっくり来た／一部違う」の反応、改善候補にする。質問、判定の重み、タイプ名を勝手に日々入れ替えない。公開する内容は一つのまま、改善の履歴は内部で管理する。

データ提供は任意。回答や性癖のタグを広告へ渡さない。すでにある収集上限とBot対策を前提に、訪問ごとの有料生成を必要としない構成を保つ。広告・アフィリエイトは、実在する掲載先と条件が決まってから診断の外側へ配置する。
